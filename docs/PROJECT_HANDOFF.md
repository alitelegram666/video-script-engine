## ۰. دستورالعمل‌های کار با Gemini

### قوانین کلی
1. **با کاربر فارسی صحبت کن.** کوتاه، صادق و دقیق. اگر چیزی را تست نکرده‌ای، بگو تست نشده.
2. **از صفر بازنویسی نکن.** کد فعلی کار می‌کند و روی سرور تست شده است. تغییرها را کوچک و مشخص بده.
3. **هر تغییر کد را به‌صورت فایل کامل یا diff دقیق بده**، با مسیر فایل. یک تکه کد بدون جای دقیقش نده.
4. **بعد از هر تغییر، روش تست را هم بگو** (دستور curl یا مراحل در مرورگر).

### محدودیت‌های سخت کاربر
- **همه‌چیز باید رایگان باشد.** هیچ سرویس پولی‌ای پیشنهاد نکن، مگر اینکه صریحاً بگویی پولی است.
- **پردازش روی سرور ابری انجام شود.** سیستم کاربر ضعیف است؛ چیزی که روی کامپیوتر کاربر اجرا شود پیشنهاد نکن.

### نام مدل‌ها و قیمت‌ها
- اسم مدل‌ها، قیمت‌ها و APIها زود عوض می‌شوند. قبل از اینکه به آن‌ها تکیه کنی، با مستندات رسمی چک کن.
- `gemini-3.5-flash` اسم پیش‌فرض در کد (`PROVIDERS` در `llm.py`) است؛ **قبل از استفاده در مستندات رسمی Gemini تأیید کن** که هنوز معتبر است.
- قیمت‌های Veo (اکتبر ۲۰۲۶): Lite ثانیه‌ای ۰٫۰۵ دلار، Fast ثانیه‌ای ۰٫۱۰، Standard ثانیه‌ای ۰٫۴۰. این قیمت‌ها ممکن است تغییر کنند.

### نقشهٔ فایل‌ها برای Gemini

| فایل | چه کاری را تغییر بده |
|---|---|
| `app.py` | endpointهای API، jobها، render، rate limiting |

| `core/audio.py` | edge-tts، faster-whisper، ffprobe |
| `core/subs.py` | زیرنویس، هم‌ترازی با اسکریپت، ASS |
| `static/engine.js` | مغز اسکریپت: plan، پرامپت‌ها، QC، آداپتور، `MODELS` |
| `static/app.js` | رفتار رابط کاربری |
| `static/index.html` | ساختار رابط کاربری (RTL) |
| `static/styles.css` | استایل |
| `Dockerfile` | استقرار روی Hugging Face Space |
| `requirements.txt` | وابستگی‌های Python |

### تغییرات امن و تغییرات خطرناک

**تغییرات امن (معمولاً بدون عوارض جانبی):**
- اصلاح نام مدل در `PROVIDERS`
- اضافه/تغییر سبک زیرنویس در `STYLES` (subs.py)
- اضافه/تغییر سبک بصری در `STYLES` (engine.js)
- اضافه کردن مدل ویدیویی جدید در `MODELS` (engine.js)
- تغییر متن‌های فارسی رابط کاربری

**دست نزن مگر اینکه لازم باشد:**
- `normalizeTimeline` (engine.js) — منطق زمان‌بندی حساس است
- `align_to_script` (subs.py) — هم‌ترازی ASR با اسکریپت ظریف است
- `qualityCheck` (engine.js) — ۱۱ بررسی قطعی
- فیلتر SSRF در `_safe_base` (llm.py) — امنیتی
- `splitClips` و `adapt` (engine.js) — آداپتور مدل
- ساختار `filter_complex` ffmpeg در `render_job` (app.py) — رندر ویدیو

## ۱. هدف پروژه

یک ابزار فارسی برای ساخت **ویدیوی کوتاه** (YouTube Shorts / Reels / TikTok، ۵ تا ۶۰ ثانیه):

```
عنوان + توضیح
  → تحلیل محتوا → کارگردان هوشمند → صحنه‌ها و سبک → کنترل کیفیت → آداپتور مدل
  → اسکریپت + Master Prompt + Shot Prompt برای Veo / Kling / Runway / Luma / Grok
  → نریشن صوتی فارسی + زیرنویس کلمه‌به‌کلمه
  → (کاربر کلیپ‌ها را در Veo یا Kling می‌سازد و آپلود می‌کند)
  → ویدیوی نهایی ۹:۱۶ با نریشن و زیرنویس سوخته
```

قابلیت مستقل دوم: **زیرنویس خودکار فارسی** برای هر ویدیو یا فایل صوتی. اگر متن اسکریپت داده شود، زیرنویس با همان متن اصلاح می‌شود.

**اصل معماری:** ابزار «مغز» کار است (اسکریپت، پرامپت، صدا، زیرنویس، مونتاژ). خودِ تصاویر ویدیو را **نمی‌سازد**؛ آن کار با مدل‌های ویدیویی است. خروجی ابزار به هیچ مدل ویدیویی‌ای قفل نیست (Model Adapter).

## ۲. تصمیم‌های کلیدی و دلیلشان

| تصمیم | دلیل |
|---|---|
| ابزار اختصاصی ساختیم، نه نصب ابزارهای آماده | هیچ ابزار آماده‌ای فارسی + ۵ سبک بصری + قوانین مدت را با هم نداشت |
| کنترل کیفیت با **کد**، نه با AI | نتیجه‌اش قطعی و قابل اعتماد است |
| زمان‌بندی صحنه‌ها با کد اصلاح می‌شود (`normalizeTimeline`) | مدل‌های زبانی در جمع‌زدن ثانیه‌ها اشتباه می‌کنند |
| متن و صدای فارسی در **مونتاژ** اضافه می‌شود، نه داخل مدل ویدیو | مدل‌های ویدیو حروف فارسی را خراب می‌کنند |
| صدای فارسی با edge-tts (Farid و Dilara) | رایگان است، زمان هر کلمه را می‌دهد |
| زیرنویس TTS از زمان‌بندی خودِ TTS + هم‌ترازی با متن اسکریپت | نیازی به تشخیص گفتار نیست، متن دقیق است |
| تشخیص گفتار با faster-whisper `turbo` روی CPU | مدل `small` فارسی را بد می‌شنید؛ turbo تقریباً دقیق است |
| اصلاح زیرنویس Whisper با متن اسکریپت (difflib) | کلمه‌های اشتباه‌شنیده با متن درست جایگزین می‌شوند |
| مغز متن: Gemini با کلید رایگان AI Studio | Free Tier مدل‌های Flash رایگان است و فارسی را خوب می‌نویسد |
| حالت بدون کلید (Pollinations) در UI مسیر اصلی نیست | در تست برای خروجی‌های بلند خطای 402 یا JSON نامعتبر داد؛ قابل اعتماد نبود. backend هنوز provider `free` دارد، اما توصیه نمی‌شود |
| «حالت دستی» نگه داشته شد | راه کاملاً رایگان بدون کلید: پرامپت در ChatGPT/Gemini رایگان چسبانده می‌شود |
| میزبانی روی pplx.app (Perplexity) | رایگان است، بک‌اند در ابر اجرا می‌شود |

## ۳. معماری

```
Browser (static/: index.html, styles.css, engine.js, app.js)
   │  همهٔ درخواست‌ها به ${API}/api/...   (API = '__PORT_8000__' proxy روی pplx.app، '' در اجرای محلی)
   ▼
FastAPI (app.py)  ── core/llm.py    → Gemini / Groq / OpenRouter / سرویس سازگار با OpenAI
                  ── core/audio.py  → edge-tts (TTS)، faster-whisper (ASR)، ffprobe
                  ── core/subs.py   → گروه‌بندی کلمه‌ها، SRT / VTT / ASS، align_to_script
                  ── ffmpeg + libass → اتصال کلیپ‌ها، تبدیل به ۹:۱۶، نریشن، سوزاندن زیرنویس
Jobs: در حافظه + فایل‌ها در /tmp/vse-jobs/{id}، حذف خودکار بعد از ۳ ساعت، صف با ۱ worker
```

### مسیر اسکریپت (`engine.js`، سمت مرورگر)
1. `plan(duration, wps)`: Duration Intelligence. تعداد صحنه‌ها، تعداد کلمه، ساختار روایت، سقف طول Hook.
2. **Stage 1** (`stage1Prompt`): تحلیل محتوا، Smart Director. خروجی JSON.
3. **Stage 2** (`stage2Prompt`): Scene Engine + Style Bible + Consistency Lock. خروجی JSON.
4. `normalizeTimeline`: اصلاح زمان‌بندی با کد.
5. `qualityCheck`: ۱۱ بررسی. اگر رد شود، یک بار Stage 2 دوباره اجرا می‌شود (Auto-repair).
6. `adapt(out, model)`: Model Adapter. کلیپ‌ها بر اساس طول‌های مجاز هر مدل تقسیم می‌شوند.

### سبک‌ها
`Smart`، `Stickman`، `Cinematic`، `PaperCut`، `Pixar3D` (هرگز اسم Pixar یا Disney در پرامپت)، `Normal`

### طول کلیپ مجاز هر مدل (`MODELS` در engine.js)
- Veo: ۴، ۶ و ۸ ثانیه (بررسی‌شده)
- Kling: ۵ و ۱۰
- Runway: ۵ و ۱۰
- Luma: ۵ و ۹
- Grok: ۶

⚠️ مقدارهای Kling، Runway، Luma و Grok **بررسی نشده‌اند** و باید با مستندات همان مدل چک شوند.

### API بک‌اند
| Endpoint | ورودی | خروجی |
|---|---|---|
| `GET /api/health` | — | وضعیت سرور، مدل‌های ASR، صداها، ارائه‌دهنده‌ها |
| `POST /api/llm` | JSON: provider, apiKey, model, baseUrl, system, user, temperature | `{ok, data}` |
| `POST /api/tts` | JSON: text, voice, rate, target, autofit, style, max_words | job + duration + cues + فایل‌ها |
| `POST /api/transcribe` | multipart: file, model, language, script, style, max_words | job (poll بگیرید) |
| `POST /api/render` | multipart: subs_job, files[] یا use_source, mux_voice, style, max_words | job → final.mp4 |
| `GET /api/job/{id}` | — | status / progress / result / error |
| `GET /api/file/{id}/{name}` | — | دانلود فایل |

خطاهای LLM با **کد 400** برمی‌گردند. پروکسی pplx.app پاسخ‌های 502 را به 503 خالی تبدیل می‌کند.

### امنیت
- CORS برداشته شده است.
- محدودیت: ۶۰ درخواست POST در هر ۱۰ دقیقه برای هر IP.
- جلوگیری از SSRF در Base URL سفارشی: فقط https و فقط آدرس‌های عمومی.
- کلید کاربر هیچ‌جا ذخیره نمی‌شود.
- provider `dev` فقط وقتی فعال است که `VSE_DEV=1` باشد؛ در نسخهٔ منتشرشده فعال نیست.

## ۴. وضعیت فعلی

- **نسخهٔ منتشرشده:** https://video-script-engine.pplx.app (عمومی)
- **روی نسخهٔ منتشرشده تست شده و سالم است:**
  - health
  - TTS فارسی با تنظیم خودکار سرعت (۲۹٫۹ ثانیه برای هدف ۳۰ ثانیه)
  - transcribe با turbo + اصلاح با متن اسکریپت
  - render: اتصال ۶ کلیپ به ۱۰۸۰×۱۹۲۰ با نریشن و زیرنویس سوخته (h264/aac)
  - حالت دستی → QC → پرامپت‌ها → صدا → ویدیو
  - مسیر Gemini تا مرحلهٔ احراز هویت (با کلید نامعتبر، خطای درست برگشت)
- **روی سرور آزمایشی تست شده:** اسکریپت‌سازی کامل با یک LLM آزمایشی → READY TO GENERATE (۱۰ از ۱۱ بررسی موفق).
- **تست نشده:** اسکریپت‌سازی کامل با **کلید واقعی Gemini** روی نسخهٔ منتشرشده.

## ۵. مشکلات و محدودیت‌های شناخته‌شده
1. بعد از مدتی بی‌استفادگی، سرور خاموش می‌شود. درخواست اول کند است و مدل Whisper دوباره بارگذاری می‌شود.
2. فایل‌ها و jobها فقط در حافظه و /tmp هستند و ماندگار نیستند. بعد از ۳ ساعت یا ری‌استارت پاک می‌شوند.
3. QC «جا شدن نریشن در صحنه» گاهی هشدار می‌دهد (LLM برای Hook متن زیادی می‌نویسد).
4. سقف تنظیم خودکار سرعت TTS بین ‎-۳۰٪ و ‎+۳۰٪ است.
5. زیرنویس ASS افکت ساده (pop/fade) دارد. هایلایت کلمه‌به‌کلمه (کارائوکه) ندارد.
6. Whisper روی CPU با ۲ هسته: ویدیوی ۶۰ ثانیه‌ای حدود ۶۰ ثانیه طول می‌کشد.
7. صداهای فارسی edge-tts فقط دو صداست: Farid (مرد) و Dilara (زن).

## ۶. نقشهٔ راه پیشنهادی (به ترتیب ارزش)
1. **تست با کلید واقعی Gemini.** اگر اسم مدل عوض شده بود، `PROVIDERS` در llm.py را اصلاح کن.
2. **ویرایش زیرنویس در صفحه** قبل از سوزاندن.
3. **هایلایت کلمه‌به‌کلمه** در ASS.
4. **هم‌ترازی نریشن با صحنه‌ها:** زمان شروع هر صحنه از زمان‌بندی TTS دربیاید.
5. **ذخیرهٔ پروژه‌ها** با یک دیتابیس رایگان یا localStorage.
6. **کاور (تامبنیل):** ساخت تصویر با یک مدل تصویر رایگان.
7. **ساخت گروهی:** چند عنوان → چند اسکریپت.
8. موزیک پس‌زمینه با ducking (ffmpeg sidechaincompress).

## ۷. اجرا و استقرار
- **محلی:** `pip install -r requirements.txt` (ffmpeg هم لازم است)، بعد `python -m uvicorn app:app --port 8000` و باز کردن `http://localhost:8000`
- **Hugging Face Space (رایگان، CPU Basic):** یک Space با SDK = Docker بسازید. Dockerfile و هدر README آماده‌اند، پورت 7860.
- **فونت:** `fonts/Vazirmatn-Bold.ttf` برای سوزاندن زیرنویس لازم است (باینری). از https://github.com/rastikerdar/vazirmatn/raw/master/fonts/ttf/Vazirmatn-Bold.ttf دانلود کنید.
- **متغیرهای محیطی:**
  - `VSE_ASR_MODEL`: مدل تشخیص گفتار (پیش‌فرض turbo)
  - `VSE_WARM`: بارگذاری مدل Whisper هنگام شروع سرور (پیش‌فرض 1)
  - `VSE_WORK`: پوشهٔ فایل‌های موقت
  - `VSE_DEV`: فقط برای تست آزمایشی
